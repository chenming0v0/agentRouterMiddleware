# Agent Relay WebUI

React 19 / TypeScript / Vite 7 / Tailwind CSS 4 / **HeroUI v3.2.5** 的中文管理界面。
仅使用根页面 `/` 与本地标签页；所有请求通过同源 `/api/*` 调用真实服务端。

## 开发与构建

使用 Node.js 24、pnpm 11（版本已写入 `packageManager`）。

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm typecheck
pnpm test
pnpm build
```

Vite 的 `/api` 开发代理目标为 `http://127.0.0.1:18851`，不占用 8080。
前端构建不需要 Go 服务在线。

产物在 `web/dist/`。Vite 设置 `emptyOutDir: false`，保留后端提供的
`dist/.gitkeep`；Go 可嵌入 `all:web/dist`。JS、CSS、图标、字体及字体许可均位于
`/assets/*`，没有运行时字体/CDN 依赖。成功构建后，`scripts/clean-dist.mjs` 才清理
不再引用的哈希资源；不会在构建开始前清空正在预览的目录，也不会删除 `.gitkeep`。

HeroUI 使用 v3 复合组件 API：`Checkbox.Content / Control / Indicator` 和布尔
`onChange`，实际用于状态码、上游启用、抖动、网络错误和自动刷新等控制。
CSS 依次导入 `tailwindcss`、`@heroui/styles`，不需要 v2 Provider 或 Tailwind 插件。

## 结构

- `src/App.tsx`：外壳、本地导航、全局保存、鉴权提示。
- `src/hooks.ts`：服务端配置快照 / 独立配置草稿，以及统计和日志轮询。
- `src/api.ts`：同源 API、超时、sessionStorage 管理令牌、401/403 处理。
- `src/lib.ts`：表单验证、供应商标识符校验与专用地址生成、格式化、数组和请求头解析。
- `src/components/ui.tsx`：HeroUI 控件、原生键盘可访问对话框、复制与正文展示。
- `src/components/LogBody.tsx`、`src/body.ts`：按需正文读取、捕获状态、文本查看与原始 Blob 下载。
- `src/pages/`：总览、供应商、重试策略、日志、日志详情和设置。
- `src/styles.css`：深色主题与桌面 / 平板 / 手机布局。

保存完整配置对象，保留顶层、重试配置和既有上游中的未知字段。统计与日志轮询
不重新拉取配置、不覆盖草稿。加载配置失败时不会创建默认配置；PUT 失败会保留草稿。
供应商表单先应用到本地草稿，再使用全局保存生效。
GET 配置返回的请求头值 `***` 是保留原值的占位标记，不会由前端重置或替换；
编辑为新值会替换，删除 JSON 键会清除该请求头。

## 供应商专用地址

每个供应商对应一个 /{标识符}/ 专用入口。标识符必须匹配 `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`
且不能是保留前缀 `api`、`assets`、`v1`、`v1beta`、`v2`（不区分大小写）。新建时可自定义，
留空会由名称生成；已保存的标识符只读且与地址永久绑定。标识符冲突或保留前缀会在进入
草稿前被拒绝，未保存的供应商只显示「保存后生效」，不生成也不能复制地址。

已保存的供应商卡片显示 `{publicOrigin}/{标识符}`，并提供「复制地址」与「复制 /v1 地址」
两个复制按钮，成功后才反馈；复制失败会提示手动选择可选中文本。地址取自
`window.location.origin`，因此本机 18851、远程主机名和随机测试端口都正确；
Vite 开发态复制后端 `http://127.0.0.1:18851`，而不是无法转发专用路径的 dev 端口。

主流程不要求填写或保存供应商 API Key：调用模型使用调用方自己的供应商 API Key
（Authorization / X-API-Key 原样转发），后台管理令牌只用于访问后台。旧的权重、
路径 / 模型匹配与附加请求头仍保留在编辑器的「旧入口兼容」折叠区，仅供不带标识符的
旧入口使用；专用地址忽略这些字段，且重试期间始终固定同一供应商。

管理员令牌只写入当前标签页的 `sessionStorage`，经 `Authorization: Bearer` 发送，
不写入 URL、localStorage 或配置文件。它与上游请求头中的模型密钥相互独立。

## 验证

`pnpm test` 使用 Node 内置测试器保留原有测试，并扩展严格数值边界、两个读取
时限、捕获完整性、长正文、二进制解码、原始字节 API / Bearer / 404 / abort，
以及供应商标识符（格式 / 保留前缀 / 大小写不敏感 / 长度 / 重复）与专用地址生成，
目前共 14 项测试，不需要额外测试依赖。

可选浏览器契约回归（使用现有 Chromium，不安装浏览器）：

```sh
CHROME_PATH=/path/to/chrome pnpm test:browser
```

脚本通过 Node 原生 WebSocket / Chrome DevTools Protocol 自动启动临时 loopback
测试服务器，使用随机端口，不连接或修改运行中的 Go 服务。需要先运行 `pnpm build`。
测试数据只存在于测试脚本，不进入生产构建；测试覆盖：

- 375、768、1024、1440 像素下无页面横向溢出。
- HeroUI 复选框、供应商增改删草稿、标识符保留 / 重复校验、请求头验证、真实 DOM 连通性按钮调用。
- 已保存供应商显示两个复制按钮且剪贴板内容精确等于 `{origin}/{id}` 与 `{origin}/{id}/v1`；
  复制不会打开编辑器；复制失败显示手动选择提示；未保存供应商显示「保存后生效」且不提供复制。
- 未知字段往返保留、轮询不覆盖草稿、失败加载禁止保存、失败保存保留草稿。
- 任意状态码、服务端正则匹配 / 未匹配 / 错误结果展示。
- 空日志、筛选、网络状态 0、预览省略与实际部分捕获的不同提示、元数据导出。
- 大于 32 KiB 的请求 / 响应 / 尝试正文尾部标记、已读取内容复制、逐字节原始下载。
- gzip 二进制下载不重编码、每次尝试的响应头、正文 404 / 401、关闭详情中止读取。
- 管理令牌会话存储、401/403 提示、关闭嵌套对话框后恢复页面滚动。

截图与下载校验文件写入已忽略的 `web/test-results/`，测试结束会关闭 Chromium 并删除
本次创建的浏览器 profile。上述测试使用 API 契约夹具，不证明 Go 后端实际行为。

### 真实 Go 浏览器联调

```sh
CHROME_PATH=/path/to/chrome pnpm test:integration
```

环境现有 Chromium 可这样执行：

```sh
CHROME_PATH=/root/.cache/ms-playwright/chromium-1208/chrome-linux64/chrome pnpm test:integration
```

需要 Go、Node.js 24、pnpm 以及已存在的 `/tmp/opencode`。脚本会重新构建当前 WebUI，
然后从仓库根目录执行 `go build -o <临时目录>/agent-relay .`，确保测试嵌入的是最新产物。
配置、二进制、日志和浏览器 profile 都放在专用 `/tmp/opencode/agent-relay-integration-*`
目录；Go 服务与本地假上游分别使用随机 loopback 端口，明确排除 8080 / 18851。
不使用 `-web-dir`，不拦截浏览器路由，不伪造 `/api` 响应。

真实测试路径：

1. 打开嵌入 UI，看到实际 401，再通过界面设置会话令牌；调用真正的 Go RE2 测试接口，
   验证匹配成功与不支持语法的错误显示。
2. 通过界面创建供应商（名称 + 自定义标识符 + 根地址），不填写任何供应商 API Key；
   保存后点击两个复制按钮，核对剪贴板内容精确等于 `{origin}/{id}` 与 `{origin}/{id}/v1`。
3. 重新加载后标识符只读且保持不变；展开「旧入口兼容」修改权重再保存，核对临时配置中
   的标识符不变，且从未写入供应商密钥。
4. POST `{复制的 /v1 地址}/chat/completions`，携带调用方自己的供应商 Bearer Key，
   经过实际 Go 代理，本地上游先返回 429、再返回 200，断言恰好调用两次、路径已剥离
   标识符前缀、且上游收到的 Key 与调用方发送的完全一致。
5. 查看实际统计与日志；按需读取请求、最终响应及两次尝试正文。
   所有测试正文均超过 32 KiB，核对末尾标记、原始内容复制及下载文件的每个字节。
6. 验证每次尝试响应头、元数据导出、移动端布局，以及静态 / 管理路由没有误入上游。

所有自己启动的子进程与临时配置 / 日志目录均在 `finally` 中关闭和清理，**不会停止
已有服务，也不会清理 `agentrouter-preview-user*` 用户预览目录**。真实截图、下载校验文件
与 Go 运行日志保留在 `web/test-results/integration/`，便于复核。
共享 CDP 驱动会激活测试标签页，避免应用按设计暂停后台页轮询。统计断言等待上限为
60 秒，覆盖管理 API 的 30 秒网络超时与后续轮询；请求 / 响应及耗时记录保存到
`api-observations.json`，不保存 Authorization 请求头。
断言截止时间使用 `performance.now()` 单调时钟，避免宿主系统时间校正造成提前超时；
每次下载校验目录由 `mkdtemp` 独立创建，避免误用上一轮文件。

## 日志正文与重试语义

- 日志 `time` 是请求开始时间；记录在请求结束后进入列表，最新记录在前。
- 列表和元数据中的正文是最多 32 KiB 的预览。`*_body_truncated` 仅表示预览可能被
  缩短，不据此判定磁盘存档不完整。
- `*_body_complete / available / error`、已观测和已存储字节数决定实际捕获状态。
  达到显式 cap、I/O 失败或连接取消时可能是部分存档，界面会说明原因。
- 打开详情只读取 `/api/logs/{id}` 元数据，不自动读取 50 条日志或所有尝试的正文。
  点击各卡片才读取 `/api/logs/{id}/body/request`、`response` 或 `attempt-N`。
  `response` 是最终上游尝试正文的别名，元数据中的 `response_body_part` 显示具体来源。
- 正文接口返回原始字节。下载始终保留 Blob，压缩 / 二进制内容不会默默转成 UTF-8；
  文本查看会校验解码。读取中的请求会在取消、切换对应内容或关闭详情时中止。
- 「复制元数据 / 导出元数据」仅包含字段及预览；完整正文请使用逐项原始文件下载。
- `max_log_body_bytes=0` 是不限长度地流式捕获到磁盘，不是把所有日志正文存入 RAM。
  正值是明确的捕获上限，最大 1 GiB。默认保留 50 条，允许 1–1000 条。
- 总尝试次数 1–20，包含第一次；权重 0–1000000，0 始终不参与路由；上游超时
  1–86400000 ms。请求体 / 缓冲区上限为 1 B–1 GiB。
- 正文嗅探时限默认 250 ms，错误正文读取时限默认 2000 ms，都允许 1–60000 ms。
  前端拒绝无效值，不静默截断或改写。
- 状态码 **或** 完整正文正则命中，只能在向客户端提交响应之前重试。
  成功 SSE 立即透传，不逐帧匹配正则。压缩、嗅探超时或超出缓冲区的正文跳过正则。
  网络错误重试默认关闭；Go 默认状态码为 400、404、429、500、502、503、504。
- 空 globs 表示显式匹配全部，不存在“回退到第一个上游”。无启用上游返回 502，
  无路径 / 模型匹配返回 404，匹配上游权重全为 0 返回 503。
- 专用地址（`/{标识符}/…`）剥离第一段后转发到该供应商根地址，忽略权重、匹配规则与
  附加请求头；停用供应商返回 503，未知标识符的 `/{标识符}/v1…` 返回 404；所有重试
  固定同一供应商。以上权重 / globs 语义仅适用于不带标识符的旧入口。
